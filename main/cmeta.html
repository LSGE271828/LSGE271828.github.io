Sinthome2026/3/11大约 4 分钟C++C++记录

($-流程记录) 分布式即时通信系统

一、Qt 客户端界面部分

本阶段首先使用 Qt Designer 完成了登录页和注册页的基础界面设计，并在 MainWindow 中声明登录页、注册页以及 QStackedWidget 页面容器对象。

页面结构如下：

MainWindow
    └── QStackedWidget
            ├── Login_Dialog
            └── Reg_Dialog

程序启动后，MainWindow 创建登录页和注册页，并通过 addWidget() 将两个页面加入 QStackedWidget。默认显示登录页面，当用户点击“注册”按钮时，登录页发出切换信号，MainWindow 接收该信号并调用 setCurrentWidget() 切换到注册页面。

这样处理后，登录页和注册页始终保存在同一个页面容器中，切换时不需要重新创建窗口，也不需要反复替换主窗口的中心部件。

二、关于未指定父对象的思考

最初创建页面对象时，我使用了下面的写法：

_login_dlg = new Login_Dialog();
_reg_dlg = new Reg_Dialog();

这里没有在构造函数中为两个页面明确指定父对象，因此我进一步思考了对象生命周期和内存释放的问题。

Qt 中大多数界面类都继承自 QObject。QObject 使用父子对象树管理生命周期：父对象销毁时，会自动销毁其子对象。因此，是否设置父对象会直接影响对象由谁管理、何时释放。

1. setCentralWidget() 会接管对象

对于登录页面：

_login_dlg = new Login_Dialog();
setCentralWidget(_login_dlg);

虽然创建时没有指定父对象，但调用 setCentralWidget() 后，QMainWindow 会接管该控件，并将其纳入主窗口的对象管理体系。因此，主窗口销毁时，登录页面也会被自动释放。

也就是说，下面的对象在执行 setCentralWidget() 以后，一般不需要再手动 delete：

_login_dlg = new Login_Dialog();
setCentralWidget(_login_dlg);

2. 未被接管的对象可能产生内存泄漏

注册页面创建后如果暂时没有加入任何容器：

_reg_dlg = new Reg_Dialog();

那么它仍然是一个没有父对象的独立对象。如果程序退出前既没有将其加入主窗口，也没有主动释放，就可能产生内存泄漏。

可以在创建时直接指定父对象：

_reg_dlg = new Reg_Dialog(this);

也可以在使用 QStackedWidget 时，将页面交给页面容器管理：

_login_dlg = new Login_Dialog(_stackedWidget);
_reg_dlg = new Reg_Dialog(_stackedWidget);

_stackedWidget->addWidget(_login_dlg);
_stackedWidget->addWidget(_reg_dlg);

即使创建页面时没有传入父对象，调用 addWidget() 后，QStackedWidget 也会重新设置页面的父对象，并负责管理这些页面。

3. 反复调用 setCentralWidget() 的隐患

最初的页面切换方式可能写成：

void MainWindow::SlotSwitchReg()
{
    setCentralWidget(_reg_dlg);
    _login_dlg->hide();
    _reg_dlg->show();
}

这种方式虽然能够完成一次切换，但不适合管理多个页面。因为 QMainWindow 会接管中心部件，当中心部件被替换后，原中心部件可能在适当时机被释放。

此时，成员变量 _login_dlg 仍然保存着原来的地址，但该地址对应的对象可能已经被删除。如果之后再次访问：

_login_dlg->show();

就可能访问已经失效的对象，形成悬空指针，严重时会导致程序崩溃。

因此，更稳定的方式是只将 QStackedWidget 设置为主窗口的中心部件：

setCentralWidget(_stackedWidget);

登录页和注册页都放在页面栈中，切换时只修改当前页面：

_stackedWidget->setCurrentWidget(_login_dlg);
_stackedWidget->setCurrentWidget(_reg_dlg);

这种方式不会反复改变中心部件，也不会在页面切换过程中删除旧页面，页面中的输入内容和状态也可以继续保留。

三、当前采用的处理方式

综合对象生命周期和页面扩展需求，最终采用如下结构：

_stackedWidget = new QStackedWidget(this);

_login_dlg = new Login_Dialog(_stackedWidget);
_reg_dlg = new Reg_Dialog(_stackedWidget);

_stackedWidget->addWidget(_login_dlg);
_stackedWidget->addWidget(_reg_dlg);

setCentralWidget(_stackedWidget);
_stackedWidget->setCurrentWidget(_login_dlg);

对象关系为：

MainWindow
    └── QStackedWidget
            ├── Login_Dialog
            └── Reg_Dialog

当 MainWindow 销毁时，会自动销毁 _stackedWidget；页面容器销毁时，又会自动销毁登录页和注册页。因此，析构函数中只需处理 ui：

MainWindow::~MainWindow()
{
    delete ui;
}

不需要重复手动释放 _login_dlg、_reg_dlg 和 _stackedWidget。

四、后续开发

完成页面容器和页面切换后，下一阶段将继续补充注册页返回登录页、输入内容校验、验证码倒计时和错误提示，并通过 QSS 统一按钮、输入框和窗口样式。

界面功能稳定后，再封装 HTTP 请求并接入 GateServer，逐步实现验证码获取、用户注册和登录功能。后续还可以继续将聊天主页、好友列表和个人信息页加入 QStackedWidget，形成完整的客户端多页面结构。
