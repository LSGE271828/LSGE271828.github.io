C++全栈项目- 分布式即时通信系统

本项目是一个基于 C++ 开发的分布式即时通信系统，主要包含桌面客户端、网关服务、状态服务、聊天服务、验证码服务以及数据存储模块。

项目客户端使用 Qt Widgets 开发，服务端使用 Boost.Asio 实现异步网络通信，并通过 Boost.Beast 搭建 HTTP 网关。不同服务之间使用 gRPC 进行通信，同时使用 MySQL 保存用户信息，使用 Redis 管理验证码、登录状态、服务器状态以及部分缓存数据。

项目整体将逐步实现以下功能：

  • 用户注册与登录；
  • 邮箱验证码获取；
  • 好友添加与好友列表展示；
  • 单聊消息发送与接收；
  • 离线消息存储；
  • 多个聊天服务器之间的消息转发；
  • 状态服务负载均衡；
  • 客户端断线检测与重新连接；
  • Windows 客户端与 Linux 云服务器部署。

本篇首先记录客户端登录界面和注册界面的开发过程。

一、客户端界面开发

1.1 创建客户端工程

首先使用 Qt Creator 创建一个 Qt Widgets Application 项目，项目名称设置为：

llfcchat

主窗口采用 QMainWindow，登录界面和注册界面分别使用独立的 QDialog 页面实现。

在 Qt Designer 中完成登录页和注册页的基础布局，包括账号输入框、密码输入框、验证码输入框以及登录、注册等按钮。

为了方便后续增加找回密码页面、聊天主页和个人信息页面，本项目没有通过反复替换 QMainWindow 中心部件的方式管理页面，而是使用 QStackedWidget 作为统一的页面容器。

整体页面结构如下：

MainWindow
    │
    └── QStackedWidget
            ├── Login_Dialog
            ├── Reg_Dialog
            ├── Forget_Dialog
            └── Chat_Dialog

QStackedWidget 可以同时保存多个页面，但同一时间只显示其中一个页面。需要切换界面时，只需要设置当前显示的页面，不必反复创建和销毁窗口对象。

1.2 登录页与注册页结构

当前阶段主要完成两个页面：

客户端界面
├── 登录页面 Login_Dialog
│   ├── 用户名输入框
│   ├── 密码输入框
│   ├── 登录按钮
│   ├── 注册按钮
│   └── 找回密码入口
│
└── 注册页面 Reg_Dialog
    ├── 用户名输入框
    ├── 邮箱输入框
    ├── 密码输入框
    ├── 确认密码输入框
    ├── 验证码输入框
    ├── 获取验证码按钮
    └── 确认注册按钮

界面开发阶段暂时不连接真实服务器，主要目标是先完成页面布局、页面切换和基本的对象管理结构。

这样可以将界面问题和网络问题分开处理，避免客户端界面、HTTP 请求和服务端逻辑同时开发时难以定位错误。

二、在 MainWindow 中声明页面对象

为了让主窗口统一管理登录页、注册页以及页面容器，需要在 mainwindow.h 中声明相应的成员变量。

#ifndef MAINWINDOW_H
#define MAINWINDOW_H

#include <QMainWindow>
#include <QStackedWidget>

#include "login_dialog.h"
#include "reg_dialog.h"

namespace Ui {
class MainWindow;
}

class MainWindow : public QMainWindow
{
    Q_OBJECT

public:
    explicit MainWindow(QWidget *parent = nullptr);
    ~MainWindow();

private slots:
    // 切换到注册页面
    void SlotSwitchReg();

    // 切换回登录页面
    void SlotSwitchLogin();

private:
    Ui::MainWindow *ui;

    // 页面管理容器
    QStackedWidget *_stackedWidget;

    // 登录页面
    Login_Dialog *_login_dlg;

    // 注册页面
    Reg_Dialog *_reg_dlg;
};

#endif // MAINWINDOW_H

这里将登录页和注册页声明为 MainWindow 的成员变量，主要有以下几个原因：

  1. 主窗口需要长期管理这些页面；
  2. 不同槽函数需要访问页面对象；
  3. 避免每次切换页面时重新创建窗口；
  4. 方便后续继续添加聊天主页等页面；
  5. 统一管理页面的生命周期。

页面之间不直接负责切换，而是向 MainWindow 发出信号，再由 MainWindow 决定显示哪个页面。

这种方式可以降低页面之间的耦合。

三、创建 QStackedWidget 页面容器

在 MainWindow 的构造函数中创建 QStackedWidget，然后将登录页面和注册页面加入页面栈。

#include "mainwindow.h"
#include "ui_mainwindow.h"

MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent),
      ui(new Ui::MainWindow)
{
    ui->setupUi(this);

    // 创建页面容器
    _stackedWidget = new QStackedWidget(this);

    // 创建登录页面和注册页面
    _login_dlg = new Login_Dialog(_stackedWidget);
    _reg_dlg = new Reg_Dialog(_stackedWidget);

    // 将页面加入 QStackedWidget
    _stackedWidget->addWidget(_login_dlg);
    _stackedWidget->addWidget(_reg_dlg);

    // 将页面容器设置为主窗口的中心部件
    setCentralWidget(_stackedWidget);

    // 程序启动时默认显示登录页面
    _stackedWidget->setCurrentWidget(_login_dlg);
}

MainWindow::~MainWindow()
{
    delete ui;
}

页面初始化过程可以概括为：

创建 MainWindow
       │
       ▼
创建 QStackedWidget
       │
       ▼
创建 Login_Dialog 和 Reg_Dialog
       │
       ▼
通过 addWidget() 加入页面栈
       │
       ▼
将 QStackedWidget 设置为中心部件
       │
       ▼
默认显示 Login_Dialog

使用这种结构后，登录页面和注册页面始终保存在页面栈中。

页面切换时只需要调用：

_stackedWidget->setCurrentWidget(目标页面);

不需要反复调用 setCentralWidget() 替换中心部件。

四、通过信号与槽切换页面

4.1 登录页面发出切换信号

用户点击登录页中的注册按钮后，登录页面不直接操作注册页面，而是发出一个切换信号。

在 login_dialog.h 中声明信号：

signals:
    void switchRegister();

然后在 Login_Dialog 的构造函数中连接注册按钮的点击事件：

connect(ui->reg_btn,
        &QPushButton::clicked,
        this,
        &Login_Dialog::switchRegister);

这里表示：

用户点击注册按钮
        │
        ▼
QPushButton 发出 clicked 信号
        │
        ▼
Login_Dialog 发出 switchRegister 信号

登录页面只负责通知外部“用户希望进入注册页面”，但不关心注册页面对象具体由谁创建，也不直接控制主窗口。

4.2 MainWindow 接收切换信号

在 MainWindow 构造函数中建立信号与槽的连接：

connect(_login_dlg,
        &Login_Dialog::switchRegister,
        this,
        &MainWindow::SlotSwitchReg);

实现对应的槽函数：

void MainWindow::SlotSwitchReg()
{
    _stackedWidget->setCurrentWidget(_reg_dlg);
}

完整的页面切换流程如下：

点击注册按钮
      │
      ▼
Login_Dialog::switchRegister()
      │
      ▼
MainWindow::SlotSwitchReg()
      │
      ▼
QStackedWidget::setCurrentWidget()
      │
      ▼
显示 Reg_Dialog

这种设计将页面内部事件和页面管理逻辑分开。

登录页负责收集用户操作，主窗口负责管理页面，QStackedWidget 负责显示指定页面。

五、注册页返回登录页

为了实现注册页面返回登录页面，可以采用相同的信号槽结构。

首先在 reg_dialog.h 中声明信号：

signals:
    void switchLogin();

在注册页面中连接返回按钮：

connect(ui->return_btn,
        &QPushButton::clicked,
        this,
        &Reg_Dialog::switchLogin);

然后在 MainWindow 中建立连接：

connect(_reg_dlg,
        &Reg_Dialog::switchLogin,
        this,
        &MainWindow::SlotSwitchLogin);

实现槽函数：

void MainWindow::SlotSwitchLogin()
{
    _stackedWidget->setCurrentWidget(_login_dlg);
}

此时登录页面和注册页面就可以进行双向切换：

Login_Dialog
      │
      │ 点击注册
      ▼
Reg_Dialog
      │
      │ 点击返回
      ▼
Login_Dialog

六、关于 Qt 父子对象机制的思考

最初创建页面时，可以直接写成：

_login_dlg = new Login_Dialog();
_reg_dlg = new Reg_Dialog();

这种写法虽然能够创建对象，但没有为它们指定父对象。

如果对象后续没有被其他 Qt 容器接管，同时程序中也没有主动执行 delete，就可能出现内存泄漏。

Qt 中的 QObject 使用父子对象树管理生命周期。当父对象被销毁时，会自动销毁其所有子对象。

因此，可以在创建页面时明确指定父对象：

_login_dlg = new Login_Dialog(_stackedWidget);
_reg_dlg = new Reg_Dialog(_stackedWidget);

此时对象关系如下：

MainWindow
    │
    └── QStackedWidget
            ├── Login_Dialog
            └── Reg_Dialog

当 MainWindow 被销毁时，会先销毁其子对象 _stackedWidget；当 _stackedWidget 被销毁时，又会自动销毁登录页和注册页。

因此在析构函数中通常不需要再次手动删除这些页面：

MainWindow::~MainWindow()
{
    delete ui;
}

如果再手动执行：

delete _login_dlg;
delete _reg_dlg;

反而可能因为对象已经被父对象释放而产生重复释放问题。

七、为什么不反复使用 setCentralWidget

一种比较直接的页面切换方式是：

setCentralWidget(_login_dlg);

进入注册页面时再调用：

setCentralWidget(_reg_dlg);

这种写法在页面较少时看起来比较简单，但随着页面数量增加，会带来几个问题：

  • 页面所有权关系不够直观；
  • 旧中心部件可能被主窗口释放；
  • 原来的成员指针可能变成悬空指针；
  • 返回上一页面时可能需要重新创建对象；
  • 页面状态不容易保留；
  • 后续增加聊天主页时管理逻辑会越来越复杂。

使用 QStackedWidget 后，所有页面都由同一个容器管理：

_stackedWidget->setCurrentWidget(_login_dlg);
_stackedWidget->setCurrentWidget(_reg_dlg);

切换过程中不会重新创建页面，用户已经填写但尚未提交的数据也可以继续保留。

因此，QStackedWidget 更适合当前这种包含多个功能页面的桌面客户端。

八、Qt 客户端后续开发步骤

完成登录页和注册页的基础框架后，Qt 客户端将按照以下顺序继续开发：

登录与注册界面
        │
        ▼
输入内容校验
        │
        ▼
QSS 界面美化
        │
        ▼
验证码倒计时
        │
        ▼
HTTP 请求封装
        │
        ▼
连接 GateServer
        │
        ▼
完成注册与登录
        │
        ▼
创建聊天主页面
        │
        ▼
接入 TCP 长连接

下一阶段主要完成：

  • 判断用户名、邮箱和密码是否为空；
  • 判断两次输入的密码是否一致；
  • 校验邮箱格式；
  • 限制验证码按钮重复点击；
  • 增加错误提示和状态提示；
  • 加载统一的 QSS 样式文件；
  • 封装客户端 HTTP 请求；
  • 接入 GateServer 的验证码、注册和登录接口。

九、本阶段总结

当前阶段完成了客户端登录页和注册页的基础开发，并使用 QStackedWidget 对多个页面进行统一管理。

本阶段涉及的主要知识点包括：

  • Qt Designer 界面设计；
  • QMainWindow 与中心部件；
  • QStackedWidget 多页面管理；
  • Qt 信号与槽机制；
  • QObject 父子对象关系；
  • 页面对象生命周期；
  • 页面之间的低耦合通信。

当前客户端还没有连接真实服务器，但页面框架已经具备较好的扩展能力。

后续新增找回密码页面、聊天主页和个人信息页面时，只需要继续将页面加入 QStackedWidget：

_stackedWidget->addWidget(newPage);

再通过信号与槽切换当前页面即可。

至此，客户端基础界面框架搭建完成。下一篇将继续实现输入校验、QSS 样式优化以及验证码请求功能。
